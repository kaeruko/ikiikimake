# メイク転写の品質診断と改善案

対象: `outputs/makeup_transfer_full/benchmark/reviews`。既存の画像、重み、学習ログ、コードを読み取り、追加の推論診断を行った結果です。この調査ではモデルの再学習や本体コードの変更は行っていません。

## 結論

主な問題は、参照メイクの色を十分に反映しない学習結果、目・唇の格子状ノイズ、閉じた口への変形不良です。教師として作った画像にも不自然な塗布があるため、学習損失・画像生成・評価の三つを修正する必要があります。

前回の実装では正常実行と数式・データ分割のテストが中心で、転写品質の合格判定が不足していました。145件のテスト成功は、自然なメイクを作れることの証明ではありません。

## 今回確認できたこと

| 確認項目 | 結果 | 意味 |
|---|---|---|
| 実際の学習データ | 有効650枚、全てFairFaceの224×224。512/66/72枚を学習/検証/テストへ分割 | `full`という名前でもFFHQは含まれない。実メイクの目の擬似ラベルも未使用 |
| 学習量 | 各部位55epoch、42,240step。幅32、batch2、strided構成 | 単純な学習回数不足とは言えない |
| 唇の検証RGB損失 | 最良epoch6: 0.010913 → epoch55: 0.034882 | 後半の学習で約3.20倍に悪化 |
| 目の検証RGB損失 | 最良epoch2: 0.007565 → epoch55: 0.017292 | 約2.29倍に悪化 |
| 保存方式 | 最終epochの重みで毎回上書き | 最良epochの重みは現状残っていない |
| 参照色への応答 | 同じ顔の3スタイル間のRGB変化量は、正解に対して目5.36%、唇14.2%、頬0.624% | 参照のメイクが変わっても出力色があまり変わらない |

参照色への応答・周期成分は、各部位のテスト48件（16枚の元画像×3スタイル）の診断です。全ての入力に完全に同一の画像を出しているわけではなく、参照スタイルへの応答が大きく縮んでいる状態です。格子模様の原因を特定の一層に断定するには、条件を一つずつ変えた比較が必要です。

診断画像: `outputs/makeup_transfer_diagnosis/lip_style_response.png`。数値は同フォルダの `collapse_diagnostic.json` と `no_transfer_baseline.json` に保存しています。

## 最優先1: 色を再現できる学習に戻す

現在のRGB損失は、alphaで重みを付けた誤差を透明な背景を含む全画素で平均しています。検証データの平均alphaは目0.0473、唇0.1095、頬0.0145であり、メイクの小さい領域ほど誤差が薄まります。一方、GANの重みは10のままです。55epoch時点の生成器損失のうちGAN項が占める値の割合は、目88.3%、唇78.0%、頬97.4%でした。これは損失値の割合であり、勾配の支配率を測定した結果ではありません。

対応案:

1. RGB誤差を `sum(alpha * abs(pred_rgb - target_rgb)) / (3 * sum(alpha) + eps)` で正規化し、メイク範囲の色間違いを明確に評価する。透明領域のalpha抑制と、塗布領域のalpha精度も分けて確認する。
2. まずGANを無効にして、少数の固定ペアの色・alphaを再現できるか確認する。その後、GANの重みを小さく追加する比較を行う。
3. 識別器には `RGB * alpha` とalphaを渡す実験を行う。現状はalphaが0でも無作為なRGBが存在し、RGB再構成損失はそれを無視する一方、識別器はその見えない色を識別に使えてしまう。
4. 唇の色回帰器だけに依存せず、マスク内の直接的な平均色・低周波の色の誤差を診断に加える。

色回帰器Cは、検証用の正解マスクでは実際の平均RGBに対するMSEが0.000555、生成マスクでは0.009063と約16.3倍悪化しました。生成画像が学習済みCの得意な分布から外れている可能性があります。Cを追加した効果は、直接色の誤差と見た目の両方で判断します。

関係箇所: `losses.py:43`、`losses.py:121`、`train.py:281`、`train.py:297`、`synthesis.py:94`。

## 最優先2: 格子模様が出にくい生成器を比較する

現在はU-Netの拡大部が転置畳み込みです。「画像を拡大してから通常の畳み込みを行う」方式への置換を比較します。転置畳み込みと識別器のstrideが周期模様を作る可能性は既知ですが、今回のモデルでそれが唯一の原因だとまでは言えません。[参考研究: Deconvolution and Checkerboard Artifacts](https://distill.pub/2016/deconv-checkerboard/)

唇・頬のRGBには弱い平滑化の制約を試し、alphaの輪郭とは別に調整します。最初から多数の損失を足すと原因を判別できないので、損失修正と生成器変更は別実験にします。

関係箇所: `models.py:57`、`models.py:65`、`models.py:75`。

## 最優先3: 閉じた口で教師画像まで崩れる問題を直す

`pair_0002`では、転写先の口内上下の間隔が約0.305pxしかない一方、正規化顔の口内間隔は512pxキャンバス上で約12.18pxあります。TPSで内外の唇を同時に合わせる際、転写先の唇マスク内で約23.95%の画素に写像の折り返しが発生しました。唇を1px膨張させた範囲の外にも、生成したlip alphaの総量の約10.75%が漏れています。

対応案:

- 転写先の外唇マスクでもalphaを制限し、歯・口内を除外する。現在の制限は顔全体と目・口内が中心で、唇の外へ飛び出た色を十分止められない。
- 開口/閉口を区別し、ほぼ重なる内唇点をそのままTPSの制約へ入れない。
- 唇の上側・下側を分けた変形や三角形ごとのアフィン変換を比較し、変形の折り返しを検出して除外する。
- 合成教師と推論で同じ部位別レンダラーを使い、正解画像の時点ではみ出していないことを確認する。

学習時の全顔TPSと評価時の部位別TPSの差も確認しましたが、3例の塗布範囲での平均RGB差は0.30～0.45/255程度でした。今回の格子模様をこの差だけで説明する根拠はありません。閉口の折り返しとモデル出力のノイズを別問題として扱います。

関係箇所: `geometry.py:171`、`geometry.py:254`、`inference.py:238`、`prepare.py:231`。

## データとメイク素材の改善

正解画像にも強すぎる色や不自然な形が見られます。自然なリップ、チーク、アイシャドウの形・境界・色の組合せを確認したテンプレート群を先に作り、合成画像を目視で選別します。閉眼、口の開閉、眼鏡、遮蔽物を含む画像は別々に検証します。

高解像度で遮蔽物の少ない顔画像、実際のメイク参照からの目の教師信号も必要です。224pxの元画像を拡大しても微細な色や輪郭情報は増えません。論文も、合成素材だけでは目の形の多様性が限られるため、実メイク画像の擬似ラベルを併用しています。[対象論文](https://arxiv.org/html/2509.02445v2)

## 次に行う比較実験

| 段階 | 実験 | 確認すること |
|---|---|---|
| A | 固定した16～32ペア、GANなしの教師あり学習 | 同じ顔に紫・赤・ピンクを与えたとき、別々の色を再現できるか |
| B | Aと同じ条件で前景の損失正規化を変更 | 色の誤差が改善するか。alphaを消すだけの解になっていないか |
| C | Bの拡大層をresize＋convに変更 | 2×2周期成分と格子模様が減るか |
| D | 安定した構成へ小さいGAN項を追加 | 色・形の精度を悪化させず質感が良くなるか |
| E | 形状修正済みの教師で規模を増やす | 閉口のはみ出し、眼鏡への塗布などが抑えられるか |

各実験で同じseed・元画像split・評価画像を使い、最終epochに加えて検証指標の最良モデルを保存します。少数ペアへの適合は配線確認であり、汎化性能の評価は未使用の顔で別に行います。まず8～10epoch程度の比較で方向を判断し、良い構成に絞って本学習へ進めます。

評価には、メイク範囲の色誤差、alphaと輪郭の誤差、周期模様、参照変更への応答、塗布対象外の画素変更、未加工画像との比較を入れます。唇・目・頬を別々に評価し、見た目が悪化した後も55epochまで続ける運用を避けます。

これらの改善は公開論文から変更する設計を含むため、論文そのものの数値再現とは区別して条件を記録します。
